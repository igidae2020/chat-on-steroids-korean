# ChatGPT 응답 지연과 COS 연결 복구

이 통합본은 2.0.11의 브라우저 복구 개선에 한국어 전송 시간 초과 감지와 Goal/Loop의 미완료 응답 재관찰을 함께 적용합니다.

## 응답이 오래 걸리거나 전송 시간 초과가 표시될 때

- 화면에서 10분 동안 변화가 없다는 경고는 ChatGPT 서버의 실패나 작업 완료를 뜻하지 않습니다.
- 실제 제공자 오류인 “메시지 전송 시간이 초과되었습니다. 다시 시도해 주세요.”와 재시도 버튼은 복구 대상으로 인식합니다. 숨겨진 안내나 대화에 인용된 오류 문구는 복구 근거로 사용하지 않습니다.
- Goal/Loop가 켜진 Pro 또는 모델이 아직 확인되지 않은 미완료 턴은 확인된 새로고침 이후 10분 간격으로 다시 관찰합니다. 새로고침 자체를 새로운 작업이나 최종 답변의 증거로 취급하지 않으며, 미완료 응답에 자동 후속 메시지를 보내지 않습니다.
- 실제 최종 답변이 확인되면 그 답변을 기준으로 다음 작업을 진행합니다. 중지·차단·Goal/Loop 해제는 계속 관찰할 권한을 주지 않습니다.

2.0.11의 브라우저 복구는 COS가 사용하는 브라우저가 종료된 경우도 다룹니다. 다른 용도의 Chrome 프로필이 실행 중이라는 사실만으로 COS 브라우저가 살아 있다고 판단하지 않습니다. 복구는 기존 작업의 소유권과 사용자 설정을 따릅니다.

## Pro에서 반복을 누르면 바로 꺼질 때

Pro를 항상 `session_finish` 전용으로 처리하던 앱 정책 때문에, 대화에서 반복을 켜도 다음 상태 조회가 꺼짐으로 되돌렸습니다. 수정본은 사용자가 해당 대화에서 직접 켠 반복을 유지합니다. Session finish 설정과 다른 대화의 기본 동작은 유지됩니다.

반복을 켤 때 이미 끝난 답변이 있으면, 기록된 완료·자동 진행 적격 증거를 기존 후속 메시지 큐에 등록합니다. 중지된 턴, 더 최신 사용자 입력·진행 중 턴, 적격 표시가 없는 과거 답변은 등록하지 않습니다. 생성 중인 Pro 응답을 완료로 추정해 보내지 않습니다.

Pro 반복 스위치 수정은 앱 코드입니다. 아래 모델 식별 수정까지 적용하려면 앱과 확장을 함께 갱신해야 합니다.

## GPT-5.6 xhigh에서도 후속 전송 없이 새로고침만 반복할 때

API 후속 지시문 생성과 ChatGPT 응답 복구는 서로 다른 단계입니다. 활동 로그에 API의 `drafted … characters`가 있더라도, 그 뒤 ChatGPT 턴의 모델 식별이나 완료 관찰이 실패할 수 있습니다.

기존 확장은 열린 모델 메뉴에서만 모델 정보를 읽었습니다. 메뉴를 닫으면 정보가 사라지고, 같은 모델을 연속 사용할 때는 모델 변경 이벤트도 다시 보내지 않았습니다. 앱은 해당 턴을 모델 미확인으로 남겨 보수적인 재관찰을 반복할 수 있었습니다.

수정본은 닫힌 선택기의 검증된 React 모델 데이터도 읽고, 실제 전송 시점의 모델·추론 수준을 해당 `turn_start`와 함께 전달합니다. 나중에 고른 모델을 과거 턴의 모델로 추정하지 않습니다. 새로고침으로 재발견한 과거 메시지를 새로운 전송으로 처리하지도 않습니다.

다른 Windows PC에 적용하는 순서:

1. 기존 앱 폴더와 압축해제 확장 폴더를 백업합니다. 사용자 설정·키·대화 데이터는 보존합니다.
2. 수정 소스에서 `npm.cmd ci`, `npm.cmd run verify`, `npm.cmd run dist:dir:x64`를 실행합니다. 패키지는 `node scripts/smoke-packaged-runtime.mjs --platform win32 --arch x64`로 확인합니다.
3. COS를 정상 종료하고 검증된 패키지를 기존 앱 위치에 적용합니다. 실제 Windows 사용자로 실행해 기존 대화와 연결이 유지되는지 확인합니다.
4. 등록된 확장 폴더에 같은 소스의 `extension` 파일을 반영한 뒤 확장을 새로고침합니다. 앱만 교체하거나 ChatGPT 페이지만 새로고침하면 확장 수정이 적용되지 않을 수 있습니다. 확장 재시작 후 이미 열린 탭에 이전 코드가 남아 반복 버튼이 반응하지 않으면, 작성 중 입력과 실행 중 작업이 없는 해당 ChatGPT 탭도 새로고침한 뒤 반복 선택값을 확인합니다. 진행 중인 다른 탭은 일괄 새로고침하지 않습니다.
5. 모델 메뉴를 닫은 상태에서 선택한 모델·추론 수준이 확인되는지, 같은 모델로 연속 전송한 턴 모두에 모델 정보가 붙는지, 완료 답변 후 자동 후속 전송이 한 번 발생하는지 확인합니다.

수정 이전에 이미 중단된 턴의 모델을 현재 선택기만 보고 소급 확정하지 않습니다. 그 대화는 작성 중 입력·실행 중 작업을 확인한 뒤 기존 작업의 계속 지시로 재개합니다.

## Pro 응답 중 모델 선택을 바꾸는 경우

모델 메뉴는 다음 전송의 선택입니다. 진행 중 응답의 완료 판정은 그 응답을 전송했을 때의 모델을 사용해야 합니다. 확장의 제한된 DOM 완료 판정도 전송 시점 정보를 사용하며, 추론 수준이 `pro`인 모든 모델은 네이티브 완료 증거를 기다립니다. 전송 모델을 모르는 응답을 나중의 Thinking 선택만으로 완료 처리하지 않습니다.

이전 응답의 종료와 새 응답의 시작이 같은 확장 전송 묶음에 들어가더라도 새 응답의 감시를 유지합니다. 새 응답까지 같은 묶음 안에서 종료되면 그 응답의 실제 결과에 따라 감시를 끝내거나 실패 복구를 유지합니다. 감시가 이미 종료된 미완료 응답을 다시 관찰할 때도 현재 모델 메뉴로 과거 응답을 재분류하지 않습니다.

## COS 보조 에이전트 사용

COS의 보조 에이전트는 Core의 `agents` 도구로 실행하는 별도 ChatGPT 대화입니다. 앱의 멀티 에이전트 설정과 해당 대화의 Core 도구 노출이 모두 필요합니다. Loop용 API는 후속 지시문을 생성하며, 그 API 선택이 보조 에이전트 실행 도구를 대신하지 않습니다.

주 에이전트는 `agents`의 `status`로 기존 작업자를 확인하고, 관련 작업을 했던 재사용 가능한 작업자는 `message`로 깨웁니다. 새 작업은 `spawn`에 공통 작업 폴더·지침·검증 명령을 `context`로, 각 작업자의 목표·수정 가능 파일을 `workers[].task`로 전달합니다. 작업자는 결과와 검증을 `finish`로 보고하며 보통 대기 상태로 남습니다. 대기 중이라는 이유만으로 새 작업자를 계속 만들지 않습니다. 결과는 후속 도구 응답으로 도착하며, 주 에이전트가 실제 변경과 검증 결과를 확인해야 합니다.

COS 작업자 슬롯은 앱 설정을 따릅니다(소스의 상한 8). Codex/OpenCodex의 별도 서브에이전트 한도와 합산하거나 동일한 기능으로 취급하지 않습니다. 이미 다른 주 대화가 실행을 소유한다면 기존 작업과 충돌하는 새 실행을 만들지 않습니다.

## COS Core의 `read`가 대화에 없을 때

`This conversation does not support developer MCPs`가 표시되는 대화는 앱 재설치만으로 해결된다고 볼 수 없습니다. 데스크톱 연결, 승인 폴더, 해당 ChatGPT 대화의 플러그인 지원 여부를 구분해 확인합니다.

1. [공식 Plugins 연결 안내](https://developers.openai.com/plugins/deploy/connect-chatgpt)에 따라 플러그인을 지원하는 새 대화에서 Chat On Steroids Core를 선택합니다.
2. COS에 이미 승인한 `<사용자 작업 폴더>`에 민감하지 않은 확인용 파일을 준비하고, Core `read`로 실제 내용을 읽게 합니다. 대화의 설명만 듣지 말고 도구 실행 결과와 파일 내용이 일치하는지 확인합니다.
3. 읽기가 확인된 대화에 목표, 완료한 내용, 남은 작업과 필요한 자료를 인계합니다. 기존 대화는 확인이 끝날 때까지 보존합니다.

새 대화를 만들거나 목표를 인계해도 기존 클라우드 작업 파일이 자동으로 옮겨지는 것은 아닙니다. 필요한 파일은 사용자가 사용할 수 있는 정상적인 내보내기·첨부 절차로 전달하고 새 대화에서 확인해야 합니다. 지원되지 않는 대화의 제한을 우회하거나, 없던 도구 권한을 있다고 가정하지 않습니다.

**자동 요약 이전이 개발자 MCP 선택과 사용 가능 상태까지 승계하는지는 검증되지 않았습니다.** 자동 요약으로 새 대화가 생겼다는 사실만으로 Core 연결 검증을 대신하지 마세요. 이전 대상 대화에서도 실제 `read`를 확인한 뒤 Windows 작업을 이어갑니다.

## 다른 대화의 도구 호출 때문에 작업 중인 탭이 새로고침될 때

이전 앱은 출처를 확인하지 못한 MCP 호출이 들어오면 활동 중인 대화들을 후보로 잡고, 연결을 복구하려고 후보 탭을 새로고침했습니다. 별도의 대화에서 정상적으로 Core를 호출해도 그 호출과 관계없는 Pro 응답 화면이 새로고침되는 문제가 있었습니다.

수정본은 출처 미확인 호출을 기록하되, 그 호출만으로 대화의 활동 시간을 갱신하거나 복구 타이머·새로고침을 만들지 않습니다. 정확히 귀속된 호출과 해당 대화 자체의 응답 오류·장시간 무변화에 대한 기존 복구는 유지합니다. 새로고침이 발생했다면 활동 기록의 이유를 확인하여 서로 구분해야 합니다.

이 수정은 앱의 `bridge.ts` 변경입니다. 앞선 확장 수정까지 이미 설치된 PC에서는 COS를 정상 종료하고 새 패키지의 앱을 적용하면 되며, 이 수정만을 위해 Chrome 전체를 재시작하거나 확장을 다시 등록할 필요는 없습니다. 다른 PC에서는 위 설치 순서에 따라 사용자 설정과 대화 데이터를 보존하고 적용합니다. 적용 후 한 대화가 응답을 생성하는 동안 다른 대화에서 읽기 전용 Core 호출을 실행하여, 출처 미확인 연결 복구를 이유로 첫 대화를 새로고침하지 않는지 확인합니다.

대화 길이 제한에 도달해 제공자가 새 입력을 거부하는 문제는 별개입니다. 기존 대화와 실제 작업 파일을 보존하고, 새 대화에서 파일·남은 목표·필요한 Core 도구를 확인한 뒤 이어갑니다. 새 탭을 만들었다거나 반복 스위치가 켜졌다는 사실만으로 복구 완료로 판단하지 않습니다.
