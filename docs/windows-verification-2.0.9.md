# 한국어판 2.0.9 Windows 설치·브라우저 검증

검증일: 2026-09-10. 대상은 공개 `v2.0.9`의 커밋
`3c91c9aec027d612846580db38e4b0c1397c90c8`이며, Windows x64 실기 1대에서 수행했다.

## 확인한 결과

- 공개 Windows x64 설치 파일의 SHA-256이 릴리스 `SHA256SUMS.txt`와 일치했다.
- 정식 설치 경로에서 실행 중인 앱의 버전은 2.0.9다. 설치 폴더를 대상으로 한
  packaged runtime smoke에서 Electron, Sharp/libvips, PNG, PTY, parser와 리소스 검사가 통과했다.
- 설치된 확장 핵심 6개 파일이 해당 커밋의 소스와 해시까지 일치했다.
- Chrome에서 확장을 새로고침한 뒤 실제 앱 로그에 확장 2.0.9 접속이 기록됐다.
  앱·확장의 bridge protocol은 14다.
- 기존 OpenCodex custom 설정과 `gpt-6-astra` / `high` 선택을 유지했다.
  실제 OpenCodex Goal 생성 probe가 통과했으며, 자동 Goal은 기존 Off 설정을 유지했다.

## 브라우저 실기

실제 사용자 작업 대신 별도의 합성 검증 대화를 사용했다. 대화에는 도구 호출이나
웹 검색을 하지 않도록 명시했으며, 사용자 파일·키·설정은 전송하지 않았다.

1. 확장 갱신 후 검증 페이지를 재로드하고 `COS209_READY` 응답을 요청했다.
   화면의 정확한 응답과 COS의 같은 turn에 대한 `turn_end: completed`를 확인했다.
2. 확장 메뉴의 **지금 요약 후 이어가기**를 실행했다. 요약 요청 후 원본 페이지를
   재로드했으며, 이후 이어가기 대화 하나가 생성되고 원본 검증 탭은 정리됐다.
3. continuation의 디스크 상태가 `committed`가 됐다. 원래 로컬 세션 ID는 유지되고
   현재 대화 ID만 대상 대화로 바뀌었다. 요약과 대상 응답 모두 검증 목적·표식을 보존했다.
4. 대상 대화를 다시 재로드해 기존 요약과 응답이 유지되고 중복 전송이 없는 것을 확인했다.
5. 재로드 후 후속 메시지를 보내 `COS209_RELOAD_OK` 응답을 확인했다.
   저장된 assistant 메시지는 `final: true`, 해당 turn은 `completed`,
   세션의 `activeTurnId`는 `null`이었다.

## 범위와 한계

- 공개 릴리스의 6개 플랫폼 빌드·패키지 검증과 위 Windows x64 실기는 별개 근거다.
- 이번 실기는 확장 갱신, 페이지 재로드, 응답 완료 감지, 수동 요약·이어가기,
  세션 유지 및 복구 후 입력을 검증했다.
- CPU 프로파일링, 모든 탭 경합 순서, 장시간 자동 Goal/Loop, 실제 400k 자동 요약,
  앱·브라우저 강제 종료 후 복구, 모든 MCP 도구의 웹 실행을 검증한 것은 아니다.
- 다른 Windows PC의 설치·실기는 수행하지 않았다.

공개 기록에는 로컬 사용자 경로, 계정 정보, 대화 URL/ID, continuation 표식,
연결 주소의 비밀값 및 실제 사용자 대화 내용을 포함하지 않았다.
