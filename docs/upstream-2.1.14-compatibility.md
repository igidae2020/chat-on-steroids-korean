## 채택 원칙

1. 같은 의도의 공식 수정이 있으면 공식 구현과 회귀 검사를 먼저 검토합니다. 제목이 비슷하다는 이유만으로 우리 실패까지 해결됐다고 간주하지 않습니다.
2. 공식 원본에서 우리 실패 사례가 통과하면 대응하는 우리 제품 코드 패치는 제외합니다. 필요한 회귀 사례만 공식 구조에 맞춰 남깁니다.
3. 실패가 남으면 현재 공식 소유권·응답 식별·전송 구조 안에서 최소 수정합니다. 옛 bridge/goal/content 파일을 통째로 덮어쓰지 않습니다.
4. 한글화·OpenCodex·우리 배포 경로는 독립 기능으로 유지합니다. 공식의 추가 언어, 파일 패널, 터미널, PDF 뷰어, 연결 진단, 스킬, 펫 기능과 의존성을 보존합니다.
5. 공식 수동 Pro 요약 1시간 정책, Stop·Block·권한·전송 규칙을 유지합니다. 실패 응답의 Continue와 완료된 답변의 Goal/Loop는 서로 다른 경로로 검증합니다.

## 공식 패치부터 검토할 지점

[공식 PR #293](https://github.com/totec448-spec/chat-on-steroids/pull/293)은 복구 기한, 요청 소유권, 대화 기록 연속성을 함께 변경합니다. 이번 고정 소스에 포함된 `bb01b7b`, `0f1d61f` 및 병합 `fbb4038`을 우선 비교합니다.

- `src/main/bridge.ts`의 `owedPickups`는 사용자 입력·미완료 Continue·최종 답변의 Goal/Loop를 같은 pickup 경로와 재로드 예산으로 조정합니다. 기존 별도 복구 경로를 위에 덧붙이지 않습니다.
- `src/main/session/store.ts`의 `readCompletedFinal`과 `src/shared/session.ts`의 `workSequence`를 함께 확인합니다. 전달/메타데이터 순번과 실제 본문 변경 순번을 혼동하지 않는지 회귀로 판단합니다.
- `extension/content.js`의 목적지 이동 및 전송 확인 경로는 최초 URL 이동·두 번째 무관한 이동·ACK 지연·백그라운드 타이머 지연을 구분해야 합니다.
- `src/main/session/continuation.ts`의 `sweep`는 committed/aborted 기록을 `CONTINUATION_TTL_MS * 2` 이후 메모리에서 정리합니다. 우리 pending Loop 근거 보존과 동등하다고 간주하지 않습니다.

공식 PR의 테스트 통과는 참고 증거이며, 우리 통합본이나 사용자의 Mac/Windows에서 수행한 결과로 표시하지 않습니다.

## 실제 이식 순서와 완료 조건

1. 확정된 공식 SHA에서 별도 통합 작업본을 만들고 공식 lockfile/의존성을 유지합니다. 공식 원본 필수 검사와 Mac 빌드를 먼저 확인합니다.
2. 공용 번역 키 → 한글화 / OpenCodex 각각 → 배포 경로 순으로 기능별 적용합니다. 한국어는 공식 추가 언어를 삭제하지 않고 저장된 사용자 선택·작성 중 입력·사용자 원문을 보존해야 합니다.
3. 아래 실패 사례를 **공식 원본 먼저**, 이후 통합본에서 검사합니다. 공식 통과 사례는 우리 중복 제품 코드 제외, 공식 실패 사례만 기존 owner 안에서 수정합니다.
4. 소스/테스트와 릴리스 번호 변경을 분리한 기능 커밋을 준비합니다. 공식 기여자의 원래 저작자·PR 출처를 보존합니다.
5. 제품 코드 이식 후 근접 검사, `npm run verify`, Mac 패키지·서명 검사, Windows 네이티브 CI를 수행합니다. 앱과 확장을 동일 통합본으로 맞춰 실제 흐름을 확인합니다. 장시간 실사용과 Windows 실사용은 직접 수행한 범위만 완료로 기록합니다.

| 실패 사례 | 필수 확인 |
| --- | --- |
| 동일 실패의 재로드 반복 | 오류 재생이 복구 예산을 갱신하지 않음, 실제 다음 응답에는 새 권한 부여 |
| 실패 후 진행 | 미완료 Continue와 완료 final 기반 Goal/Loop를 각각 검사, 대기시간만 늘려 통과시키지 않음 |
| 늦은 final·과거 메타데이터 | 과거 재생은 완료를 취소하지 않음, 실제 새 본문/새 질문은 예전 완료를 무효화 |

## 이번 작업 기록과 실제 검증 범위

- 소스/릴리스 기준 조회, 공식 main fetch, 두 담당자의 제품/복구 경로 읽기 검토를 수행했습니다.
- 임시 Git 인덱스만 사용해 13개 이식 가능 패치를 의존성 순서로 확인했습니다. 전체 패치와 소스·테스트만의 적용 결과를 분리했습니다. 과거 배포 커밋은 의도적으로 제외했습니다.
- 공용 카탈로그 키만 임시 인덱스에서 조정한 추가 검사에서 OpenCodex 소스·테스트 패치는 적용됐고, 한글 UI에는 4개 소스/테스트 파일의 문맥 충돌이 남았습니다.
- 한국어 누락 키 262개, 자리표시자 키 20개와 파일별 충돌 결과를 [기계 판독용 검토 자료](upstream-2.1.14-compatibility.json)에 보관했습니다. 키 수는 공식 카탈로그의 합집합 기준이며 모두 현재 화면에서 사용된다는 뜻은 아닙니다.
- 이번 변경은 준비 문서와 근거 JSON입니다. 제품 소스·실행 중 앱·확장·설정·키·대화는 변경하지 않았습니다. 전체 테스트·빌드·설치·API 호출은 수행하지 않았습니다.
- 문서/JSON 검증 통과: 13개 이식 가능 패치의 선언된 의존성·원본 SHA 대응, 고정 Git 객체 존재, JSON 파싱, 상대 링크, 새 파일의 공백/개행 및 `git diff --check`를 확인했습니다.
