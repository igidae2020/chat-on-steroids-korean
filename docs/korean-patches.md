# 공식 업데이트에 우리 패치 옮기기

현재 한국어판은 공식 **v2.1.13** (`a4fe9726232edfbf67b97d6c716b6f653284739a`)에 우리 변경을 적용한 것입니다. 공식 파일 전체를 옛 포크로 덮어쓴 구성이 아닙니다. 앱 버전 **2.1.18**은 이 공식 기반의 한국어판 개정 번호입니다.

2.1.17의 완료 확인 수정은 별도 기능 커밋 `39345e7`입니다. `fix/historical-completion-gate` 브랜치에서 가져올 수 있으며 기존 `patches/upstream-2.1.13-korean`은 2.1.16 분할 기준을 유지합니다. 이 추가 패치는 기존 한글화·API·요약 패치와 독립적으로 적용할 수 있습니다. 새 공식 버전에서 동일 결함이 해결됐는지 먼저 확인하세요.

2.1.18의 자동 이전 직후 누락된 Loop 연결은 별도 기능 커밋 `f4ea924`입니다. 같은 수정 브랜치에 있으며 완료 확인 패치 `39345e7` 이후에 적용합니다. 버전·배포 기록과 분리돼 있습니다.

기능 커밋은 `patches/upstream-2.1.13-korean`에 보관합니다. 이 브랜치는 공식 태그에서 바로 시작하는 선형 패치 모음이며 옛 포크의 병합 이력을 포함하지 않습니다. PR용 `integrate/upstream-2.1.13-korean`에는 기존 origin/main과 연결하기 위한 별도 병합이 들어갈 수 있습니다. **다음 공식 버전에는 아래 기능 커밋을 골라 적용하고, PR의 이력 연결용 병합은 가져가지 않습니다.**

전체 SHA, 파일 목록, 의존 관계는 [korean-patch-series.json](korean-patch-series.json)에 있습니다. 각 커밋 본문에도 안정적인 `Patch-ID`와 `Depends-On`을 적었습니다. 새 공식 기반으로 이식하면 새 SHA를 기록한 별도 목록을 만드세요.

- 한글 UI와 OpenCodex는 서로 독립적으로 적용할 수 있습니다. 둘 다 작은 공용 번역 키 커밋 `cc3019c8cc`을 먼저 적용합니다. 한글 UI만 적용해도 API 프리셋은 추가되지 않으며, OpenCodex만 적용해도 UI 언어는 바뀌지 않습니다.
- 응답 식별 수정 `3878ad22e9`은 앞 회귀 검사 커밋의 대화별 테스트 헬퍼를 사용합니다. 제품 코드가 테스트 정책에 의존하는 것은 아닙니다.
- 백그라운드 요약 전송 확인 `b94c081777`은 최초 전송/목적지 식별을 추가한 `6fbb1da6b1`을 필요로 합니다. 공식이 앞 수정을 이미 포함한다면 해당 식별 계약이 동등한지 확인한 뒤 적용합니다.
- `b30369bcf2`과 `376898b1ef`는 테스트 전용입니다. 공식의 동작을 옛 정책으로 바꾸지 않습니다.
- 업데이트 저장소 전환 `fe82fb10a0`에는 앱 버전 변경을 섞지 않았습니다. 기존 `2.1.16` 버전·배포 기록 커밋은 다음 공식 릴리스에 그대로 적용하지 마세요.

## 적용 예시

아래 `v2.1.14`는 향후 공식 릴리스가 실제로 나왔을 때의 예시입니다. 실행 전에 공식 릴리스와 태그를 확인하고, 새 작업 브랜치의 시작점으로 해당 공식 커밋을 사용하세요. 공식 태그를 별도 remote ref로 받아 우리 배포 태그와 충돌하지 않게 합니다.

```sh
git fetch origin patches/upstream-2.1.13-korean
git fetch upstream refs/tags/v2.1.14:refs/remotes/upstream/releases/v2.1.14
git switch -c integrate/upstream-2.1.14-korean refs/remotes/upstream/releases/v2.1.14
```

한글 UI만:

```sh
git cherry-pick cc3019c8cc 2513f2e92e
```

OpenCodex만:

```sh
git cherry-pick cc3019c8cc afede36084
```

두 기능을 함께:

```sh
git cherry-pick cc3019c8cc 2513f2e92e afede36084
```

나머지 복구 수정은 새 공식 소스와 재현 검사를 대조해 이미 반영됐으면 제외합니다. 전체 목록을 검토한 뒤 모두 필요하다고 판단한 경우의 순서는 다음과 같습니다. **각 예시는 새 공식 기반에서 시작하는 별도 선택지이며 연달아 중복 적용하지 않습니다.**

```sh
git cherry-pick cc3019c8cc 2513f2e92e afede36084 4d785ed72d b30369bcf2 3878ad22e9 6fbb1da6b1 b94c081777 376898b1ef fe82fb10a0
```

`git format-patch -1 <SHA>`로 필요한 커밋 하나를 패치 파일로 내보내 `git am`으로 적용할 수도 있습니다. 옛 통합 PR의 전체 변경 범위를 통째로 가져오거나, `ours`/`theirs`로 파일 전체 충돌을 일괄 처리하지 마세요.

## 공식 우선과 검증

1. 먼저 새 공식 원본의 필수 검사와 대상 플랫폼 빌드를 확인합니다.
2. 한글화·OpenCodex는 필요한 것만 적용합니다. 충돌 시 공식 구조·새 기능·권한·전송 규칙을 유지하면서 기능의 최소 변경만 조정합니다.
3. 복구 수정은 같은 실패가 새 공식에서 재현될 때만 이식합니다. 공식의 수동 Pro 요약 1시간 정책을 옛 6시간 정책으로 되돌리지 않습니다.
4. 이식 후 `npm run verify`와 Mac 패키지/서명 검사, Windows 네이티브 CI를 수행합니다. 실제 전송·후속 진행·요약 이전·브라우저·스킬을 설치본에서 확인합니다.
5. 버전·기반 정보는 `package.json`, `package-lock.json`, `extension/manifest.json`, `src/main/version.ts`에서 새 배포에 맞춰 갱신하고 릴리스 노트를 새로 작성합니다. 우리 개정 번호와 공식 기반 버전을 구분합니다.

이 커밋 분리는 검증된 `ffedb6d`의 추적 파일 내용을 정확히 보존한 상태에서 수행했습니다. 기능 커밋을 전부 적용한 트리 SHA는 `02568ab964b9b057593303da75ccd95852581cd3`로 분리 전과 같습니다. 그 뒤 추가한 것은 이 안내와 커밋 목록뿐이며, 설치된 앱·확장·설정은 변경하지 않습니다. 기능을 단독 cherry-pick한 검증 결과는 통합 PR에 남깁니다.
